# Web Developer at GenDigital Academy

Part-time web developer role, roughly one year

## Overview

Maintained and restructured GenDigital Academy's website and CMS, built on Wix, so non-technical staff could manage content confidently without developer support. First experience designing systems for people who weren't developers, not just for end users.

## The Problem

GenDigital Academy runs digital literacy programmes across Indonesia, and the website needed to grow alongside them without requiring technical expertise for every update. The job wasn't to rebuild the site, it was to make an existing platform easier to maintain and expand.

## What I Built

Most of the work was structural: creating new pages, reorganising CMS collections, and cleaning up inconsistent content so future updates were easier to make correctly. The feature I'm most proud of is the events page, built using the CMS's collections and filtering functionality so visitors could browse different events dynamically instead of relying on a static list someone had to update by hand every time. Getting the collections structured so filtering actually worked cleanly took a few iterations, but once it clicked, staff could update the events section themselves without touching layout or code.

## Why It Mattered

Designing for non-technical maintainers changes the calculus. Content had to be organised clearly enough that someone without a development background could confidently make changes, which meant thinking about the CMS structure itself as part of the deliverable, not just the pages it rendered.

Beyond the site itself, I also spent time supporting the programmes it existed for, documenting teaching sessions, helping instructors, and interacting with participants during workshops and competitions. Watching instructors teach children, teenagers, and adults with very different levels of comfort with technology gave me a clearer sense of who I was actually building for. That exposure shaped several of the CMS decisions above more directly than it might look on the surface.

## Outcome

This project had less technical complexity than the others in my portfolio, but it shaped how I think about access and usability. Software that only works if a developer maintains it isn't solving the actual problem. The best technical solution is the one the people relying on it can actually use.

**Highlights**
- Reorganised CMS collections and content structure for long-term maintainability
- Built a dynamic events page using CMS filtering, replacing a manually maintained static list
- Documented changes so future non-technical contributors could update the site independently
- First hands-on experience with CMS collection design
